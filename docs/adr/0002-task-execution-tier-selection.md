# ADR-0002: 定时任务执行档选择（脚本 / 工作流 / 智能体）

日期：2026-06-13 · 状态：已采纳

## 背景

定时任务有三种可能的执行形态，能力与成本/可靠性呈反比：

```
机械确定性 ───────────────────────────────► 开放式认知
  脚本(script)      工作流(workflow)        智能体(agent)
  零 LLM/run        固定 DAG + 有界 LLM 步   开放 ReAct 循环
  最便宜/最可靠      中等                     最贵/最脆弱
```

一个机械任务（抓网页→正则提取→格式化→入库）若被错误地放进开放式
ReAct 循环（agent），会引入一整类本不存在的故障：弱模型不收敛、重复
调用烧光 token 预算、工具审批在无交互会话下失败、上下文跨 run 膨胀。
本次百度热搜采集任务正是因为提示词含"总结/用 browser 工具"被判为 agent，
随后踩了上述全部坑。

## 决策

### 执行档判定矩阵

| 任务形态 | 档位 | 判据 |
|---|---|---|
| 抓取/采集已知数据源 → 解析 → 格式化 → 存储/通知；周期数据收集；API 轮询 | **脚本** | 确定性，无需推理，可复现，零 per-run LLM 成本 |
| 接收/抓取内容 → **单次有界 LLM 调用**（摘要/分类/抽取）→ 存储/通知 | **工作流** | 需认知但流水线固定，不需要开放循环 |
| 步骤事先未知的开放式监控/判断（"盯住 X，判断哪些重要并采取相应动作"） | **智能体** | 真正需要 ReAct 动态推理 + 动态工具选择 |

### 当前实现（两档）+ 演进路径

`cron.ClassifyTaskMode` 编译期做确定性关键词判定：
- 含认知动词（总结/分析/评估/判断/挑选/解读/诊断/撰写…）→ `agent`
- 其余（采集/抓取/收集/整理/格式化/下载/同步…）→ `""`（脚本）

判定保守：误判机械任务为 agent 只是多烧 token（有重复调用守卫与自愈兜底），
误判认知任务为脚本会编出不可用脚本（自愈桥兜底）。

**工作流档暂不单独实现**，理由是脚本 + 硬化后的 agent 已覆盖现实需求，
为之引入独立 DAG 引擎属投机建设。其价值（固定流水线含单次有界 LLM 步）
真实但边际，列为后续档位：仓库已有 `engine/orchestrator.go` +
`api/workflow_runtime.go` 基础设施可承接。**触发建设的判据**：出现一类
"必须含 LLM 步、但用 agent 开放循环又过度脆弱/昂贵"的高频任务时再做。

### 脚本档的健壮性约束（编译器系统提示词强制）

1. **仅标准库**：网络用 urllib.request，解析用 re/json/html.parser；禁止
   requests/httpx/beautifulsoup（沙箱装不可靠 + 旧 TLS 握手易失败），deps=[]
2. **URL 逐字使用**：禁止臆造端点；https 握手失败自动改 http:// 重试
3. **输出契约**：末行 `print(json.dumps({"status": ..., "data": ...}))`

### 脚本档的沙箱边界（明确非容器隔离）

脚本在**本应用 Go 进程的子进程**（python3）中执行，**不是**容器/VM。隔离手段：
- **编译期**：Python AST 扫描禁用 os.system/subprocess/eval/exec/compile/ctypes/builtins
- **运行期**：context 超时 → SIGKILL；按 hash 缓存的独立 venv；独立工作目录；
  **最小化环境白名单**（仅 PATH/HOME/LANG/SSL_CERT_* 等，不透传 API key 等 secret）
- **未隔离**：网络（脚本可访问任意 http）、文件系统（同用户读写权限）。
  单用户桌面场景可接受；多租户部署需补 OS 级沙箱（namespace/seccomp）

### agent 档的安全网（误用兜底）

即使机械任务被误判为 agent，下列守卫确保不再失控：
- 重复工具调用守卫（同 tool+args 超阈值短路，逼模型用已有结果作答）
- 系统派发工具权限自动放行采集类白名单 + 能力变更类仍拒
- 无状态上下文（不加载历史，避免跨 run 膨胀）
- 工具地板（核心采集工具不被 MaxTools 截掉）
- 双语 TASK_STATUS 结果契约（失败如实记录）

## 后果

- 机械任务回到脚本档：确定性、零 per-run 成本、无工具循环故障
- 认知任务用硬化后的 agent：安全、可观测、失败可见
- 工作流档作为文档化的未来档位，不投机建设
- 选档逻辑集中在 `ClassifyTaskMode`，未来可平滑升级为编译器 LLM 判定而不改调用契约
