## 3. 风险与诚实 gap（🟡，全部已知/有兜底）

- **F-1 桌面无入口（🟡，已决策）**：`tasks.ts:146-152`/`284-287` 建任务请求体只发 `name/schedule/prompt/deliver`，**不含 `continuous`**——特性目前仅 API 可达，桌面 UI 未接。**用户已拍板延后前端开关**（按原型权威规则）。判定 🟡 而非 🔴：非"前端有入口后端硬失败"，而是新能力 UI 显式延后。
- **F-2 无进展仅识别字面重复（🟡，backstop 兜底）**：`normalizeProgress` 只比对小写折叠后的字面相等；模型每 tick 换措辞但无实质推进时停滞闸不触发，靠 `maxContinuousTicks=100` 总量 backstop 兜底（最坏空转 100 次）。属语义 vs 字面的固有局限，有硬上限封口。
- **F-3 C1 ingest 守卫可能误判非入库 tick（🟡，边界）**：prompt 含「知识库/入库」→ `jobRequiresIngest=true`；某个 tick 若合理地"只规划不入库"，`runAgentJob` 的 C1 守卫判其 failed → 检查点不推进。多数「持续整理进知识库」任务每 tick 都入库，不触发；混合型长任务是边界。
- **F-4 双契约并存（🟡，已真机验证可用）**：agent 同时收到 `PROGRESS/TASK_COMPLETE`(compose) 与 `TASK_STATUS`(NewCronDispatchMessage) 两套尾标记契约。两解析器是独立行扫描、顺序无关，真机 DeepSeek-V4-Pro 正确并存；弱模型理论上可能混淆。低风险。
