## 2. 四缺陷修复 + RED 取证（Phase 3）

### ① 跨树「总量闸」→ 组合式 fan-out 失控（最值得修）
- **根因**：深度闸/并发闸/单次数量闸各只钳一层；跨深度×跨监工轮组合相乘无总顶，墙钟只兜时间不兜数量。
- **修法**：`fanoutBudget`（atomic CAS 精确封顶）+ `withFanoutBudget`（根铸/后代复用同指针，经 `executeFunc→Process` 透传整棵树）+ `maxTotalFanout=128`/`SetMaxTotalFanout`；orchestrate/spawn 真派发前 `tryAcquire`，触顶拒派（复用不占额，refused→error 报告）。
- **RED/GREEN**：禁用闸 → 嵌套树 72、spawn 链 10（爆炸复现）；启用 → 钳在 max。锁 `multiagent_remaining_fixes_20260627_test.go`。

### ⑤ code_exec 授权令牌化（根治，非仅提门槛）
- **根因**：`source==solve && spawn_depth>0` 两字段都来自可伪造的 `msg.Metadata`，伪造顶层消息同塞即越权放行 code_exec（RCE 面）。
- **修法**：不可伪造 typed-ctx `withSolveGrant`/`solveGrantFromContext`；permission 仅凭 grant 放行（删 metadata 串判据）；solve 派子时盖 grant，经 Process 透传到闸。grant 只授权 code_exec、不越权 shell、不泄漏普通 spawn。
- **RED/GREEN**：恢复 metadata 判据 → 伪造双字段被放行（漏洞复现）；grant-only → 伪造被拒、真 grant 放行。锁 design_fixes ForgedSolve + solve_20260627 + remaining_fixes SolveGrant。

### 🟡 registry 合并落盘
- **根因**：每次 Start/Finish 在 `mu` 锁内全量 `MarshalIndent` 重写 → fan-out 2N 次全文件写 + 锁内串行化并行。
- **修法**：marshal+write 移出 `mu`、独立 `writeMu` 串行化；`persistGen`/`writtenGen` 代号合并并发写；值拷贝快照避免与并发 Finish 竞态；**全同步无后台 goroutine**（零泄漏）。
- **RED/GREEN**：禁用合并 → 40 变更=40 写；启用 → 40→2 写、落盘在飞期间数据变更不被阻塞。锁 `subagent_registry_persist_20260627_test.go`（-race）。

### 🟢 resume reuse key 碰撞
- **根因**：`reuse[agent\x00task]→单值`，上次运行同 (agent,task) 多个成功子只留最后一条、丢前者输出并逼重跑。
- **修法**：`map[string][]agentResult` FIFO 队列，同 key 多条各复用一次。
- **RED/GREEN**：覆盖语义 → 丢 OUT_ONE；FIFO → OUT_ONE+OUT_TWO 都复用。锁同 ① 文件。
